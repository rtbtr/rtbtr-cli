# Crypto Invariants

- [tested] C-01: `DeriveX25519KeyPair(ed25519Seed []byte)` accepts only a 32-byte Ed25519 seed, clamps the private key bits per RFC 7748, and deterministically returns 32-byte X25519 private and public keys using `crypto/ecdh`; invalid seed lengths return an error.
- [tested] C-02: `FetchRecipientKey(baseURL, org, bot)` performs unauthenticated `GET {baseURL}/orgs/{org}/bots/{bot}`, decodes the URL-safe-base64 `public_key` field to a 32-byte Ed25519 public key, and returns an error mentioning `not found` on 404 or when the key is missing.
- [tested] C-03: `Encrypt(plaintext, recipientX25519Public []byte)` generates an ephemeral X25519 keypair, derives a 32-byte AES-256-GCM key via X25519 ECDH plus HKDF-SHA256 with `info="rtbtr-v1"`, uses a random 12-byte nonce, and returns `nonce || ciphertext || tag` plus a 32-byte ephemeral public key; repeated encryptions are non-deterministic.
- [tested] C-04: `Decrypt(ciphertext, ephemeralPublic, recipientX25519Private []byte)` derives the same AES-256-GCM key, requires ciphertext length of at least 28 bytes, splits the first 12 bytes as the nonce, and returns an error on too-short input, ECDH failure, wrong key, tampering, or AEAD open failure.
- [tested] C-05: `Ed25519PublicToX25519(ed25519Public []byte)` converts a 32-byte Ed25519 public key to the corresponding X25519 public key via the Edwards-to-Montgomery birational map; invalid input length returns an error.
