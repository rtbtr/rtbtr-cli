# Signing Invariants

- [tested] S-01: signing.Sign(req *http.Request, seed []byte, keyID string) error adds Signature-Input and Signature headers to req conforming to RFC 9421. The signature base covers the @method, @target-uri, and @authority derived components. The Signature-Input header uses parameters created (Unix timestamp), nonce (random 32-character hex string), keyid (the provided keyID), and alg ("ed25519"). The Signature header value is a standard base64-encoded Ed25519 signature of the signature base, wrapped in colons per Structured Fields byte-sequence syntax.
- [tested] S-02: signing.Sign returns a non-nil error if the seed length is not exactly 32 bytes (ed25519.SeedSize).
- [tested] S-03: The Ed25519 signature produced by signing.Sign is verifiable: given the same request and the corresponding public key, reconstructing the signature base from the Signature-Input header and verifying with ed25519.Verify succeeds.
- [untested] S-04: `signing.Sign(req *http.Request, seed []byte, keyID string, body []byte) error` preserves prior behavior when `body` is nil; when `body` is non-nil it computes and sets `Content-Digest: sha-256=:<standard-base64(SHA-256(body))>:` and includes `"content-digest"` in the covered RFC 9421 signature components alongside `@method`, `@target-uri`, and `@authority`.
